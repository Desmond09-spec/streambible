# The OWASP Top 10: A Comprehensive Guide

The **Open Worldwide Application Security Project (OWASP)** Top 10 is a standard awareness document for developers and web application security. It represents a broad consensus about the most critical security risks to web applications. 

The current version is the **OWASP Top 10 - 2021**. Here is a detailed breakdown of each vulnerability category:

## A01:2021 - Broken Access Control
Access control enforces policies such that users cannot act outside of their intended permissions. Failures typically lead to unauthorized information disclosure, modification, or destruction of all data.
* **Example:** A standard user changing a parameter in a URL (e.g., `?role=admin`) to gain administrative privileges, or accessing someone else's account by modifying an account ID in an API request.

## A02:2021 - Cryptographic Failures
Previously known as Sensitive Data Exposure, this focuses on failures related to cryptography (or lack thereof) which often lead to sensitive data exposure or system compromise.
* **Example:** Transmitting passwords, credit card numbers, or health records over plain HTTP without TLS encryption, or storing passwords using weak/deprecated hashing algorithms like MD5 or SHA-1.

## A03:2021 - Injection
Injection flaws occur when user-supplied data is not validated, filtered, or sanitized by the application. This allows an attacker to send hostile data to an interpreter.
* **Example:** SQL Injection (SQLi) where an attacker enters SQL commands into a login form to bypass authentication or extract the entire database. Cross-Site Scripting (XSS) is also now included in this category.

## A04:2021 - Insecure Design
This category focuses on risks related to design flaws. It highlights the need for threat modeling, secure design patterns, and reference architectures. An insecure design cannot be fixed by a perfect implementation because the core logic is flawed.
* **Example:** An application that requires users to answer a weak security question (e.g., "What is your favorite color?") for password recovery, making it easily guessable by attackers.

## A05:2021 - Security Misconfiguration
This is often the result of insecure default settings, incomplete configurations, open cloud storage, misconfigured HTTP headers, and verbose error messages containing sensitive information.
* **Example:** Leaving a cloud storage bucket (like AWS S3) open to the public, or failing to remove default administrator credentials (e.g., `admin/admin`) from an out-of-the-box software installation.

## A06:2021 - Vulnerable and Outdated Components
Applications often use open-source components (libraries, frameworks) to speed up development. If these components have known vulnerabilities and are not updated, the application becomes an easy target.
* **Example:** Continuing to use an old version of Apache Struts or a logging framework like Log4j that has a known remote code execution (RCE) vulnerability.

## A07:2021 - Identification and Authentication Failures
Previously known as Broken Authentication, this relates to improperly handling user identity, authentication, and session management.
* **Example:** Permitting automated brute-force attacks against the login portal, or allowing weak passwords like "Password123" without enforcing Multi-Factor Authentication (MFA).

## A08:2021 - Software and Data Integrity Failures
This focuses on making assumptions about software updates, critical data, and CI/CD pipelines without verifying integrity. This category also includes insecure deserialization.
* **Example:** An application relies on plugins from untrusted sources, or an attacker exploits the auto-update functionality to distribute malicious updates (similar to the SolarWinds supply chain attack).

## A09:2021 - Security Logging and Monitoring Failures
Without proper logging and monitoring, breaches cannot be detected. Attackers rely on this lack of visibility to extract data and establish persistence.
* **Example:** An application doesn't log failed login attempts, or the logs are only stored locally and an attacker deletes them after breaching the server to cover their tracks.

## A10:2021 - Server-Side Request Forgery (SSRF)
SSRF flaws occur whenever a web application is fetching a remote resource without validating the user-supplied URL. It allows an attacker to coerce the application to send a crafted request to an unexpected destination.
* **Example:** A web application lets users fetch an image via a URL. An attacker supplies an internal cloud metadata URL (e.g., `http://169.254.169.254/latest/meta-data/` on AWS) to extract sensitive cloud IAM credentials.
